  ## 3. Minimal venue-name denylist

  - Scan target: production text from every src/**/*.rs, using the existing production_text canonicalization to remove comments and #[cfg(test)] bodies.
  - Allowlist: only normalized paths under src/bolt_v3_providers/**.
  - Forbidden outside that prefix: ==/!=, .eq*, .contains/.starts_with/.ends_with, matches!, if let/while let, or literal match arms where one side/scrutinee
    is a syntactic venue-identity read.

  - Important rescope: match any string literal, not a copied list of polymarket, binance, etc. If code compares venue_id to a literal, it is venue-specific
    behavior regardless of whether the fence knows that venue yet.

  - Anti-staleness: no per-line allowlist and no source-context key. The stable key is simply (rule_id, normalized path); provider exemption is path-prefix
    based. New venues require no fence edit. Any exceptional core branch must be replaced by a ProviderBinding capability, not registered as an exception.

  - Verifier self-tests: one fixture for each forbidden syntax, raw/byte string variants, comments/non-venue matches as negatives, a provider-path exemption,
    current-tree clean, and fail-closed empty discovery.

  This is essentially the deleted fence’s lexical scanner with its copied _VENUES table removed. It mechanically guards the invariant without recreating line-
  keyed registry tax.

  Reconciled keep floor: about 360 rows if GLM’s 281 is the aggressive baseline plus these 79 restored invariants—closer to GLM than Kimi, while still showing
  GLM dropped substantial real behavior.
