  ## Part 2 — concrete thin-fence answer

  Can it be built without re-creating the churn? Yes, but only as a structural provenance fence—not as a general literal classifier.

  A workable design has three layers.

  1. Compiler-enforced boundaries

     Runtime-sensitive values must cross named constructors or modules:
      - Config-derived durations, IDs, quantities, prices, URLs, and provider identities.
      - Protocol/ABI constants.
      - Algorithm constants with evidence.

     Use sealed types where proportionate. For external types, stock Clippy’s disallowed-methods, disallowed-types, and disallowed-fields can prohibit raw
     constructors outside approved boundary modules. This is type/path-resolved, so imports, aliases, and UFCS do not reopen the simple rename hole.

     cargo-deny cannot help; this repository’s deny.toml:1 governs dependencies, licenses, and advisories—not source expressions. A custom Clippy/HIR lint
     would be powerful but disproportionate unless raw primitive values remain unwrapped.

  2. Thin Python ownership fence

     Scan all production src/**/*.rs through the surviving scripts/verify_bolt_v3_provider_leaks.py:900, then flag:
      - Sensitive constructors outside approved config/protocol/algorithm boundary modules.
      - Raw provider/reference-key declarations or string projections outside their serde/NT boundary.
      - Runtime-sensitive constants outside an approved declaration macro/module.
      - Config defaults or fallback literals outside the config-loading boundary.
      - Evidence declarations whose referenced test/source/fixture no longer exists.
      - Missing required fences or paired self-tests.

     Its configuration should list types, constructors, owner modules, and evidence categories, never literal values or source lines.

     Approved stable constants can use a local declaration form such as an invariant_const! macro referencing an evidence symbol. Changing the value does not
     change the fence configuration; the KAT or fixture catches the semantic drift.

  3. Mutation and false-positive fixtures

     Required planted failures should include:
      - Direct literal timeout.
      - Literal moved through a renamed variable.
      - Local const/helper indirection.
      - Imported alias and UFCS constructor.
      - Hardcoded provider identity after NT conversion.
      - Quantity/price literal.
      - Display/serde string round-trip comparison.

     Also prove that diagnostics, tests, pure code-owned schema names, and approved protocol/KAT declarations remain accepted.

  A Python rule based only on variable names, field suffixes, or direct literal arguments is not acceptable. If v2 insists that this one script alone proves
  all of AGENTS.md rule 1, the blocker remains.

  ## Part 3 — recommend four PRs

  The current three-PR cut puts value tests and the new fence in the same PR as the sealed-type migration. That violates the spirit of pin-before-change and
  makes the highest-risk new guard difficult to review independently.

  Use four:

  1. PIN / INVENTORY

     Crosswalk schema and validator, non-row compatibility inventory, all compatibility/value/source evidence, independent deny-list completeness tests, and
     typed-declaration fixtures. No runtime behavior changes.

  2. GUARD

     Thin structural fence, Clippy boundary configuration where useful, required-fence manifest, and planted-mutation/false-positive tests. Prove it against
     the unchanged production tree.

  3. TYPE

     Migrate client-provider and reference-provider identities, NT conversion, artifacts, maps, and dispatch APIs. This PR is reviewable solely against
     already-pinned behavior and already-active guards.

  4. DELETE

     Remove the blanket registry/verifier and all exact wiring/documentation references. The crosswalk completion gate must report zero pending destinations.

  If constrained to three, merge PIN and GUARD—not GUARD and TYPE. PR2 should remain a type-only migration.

  The presence manifest also needs defined ownership: scripts/run_fences.py:177 must load the manifest first and fail on a missing required fence, missing
  paired test, or duplicate entry. production_text is correctly preserved because it is owned by the surviving provider-leak verifier.
