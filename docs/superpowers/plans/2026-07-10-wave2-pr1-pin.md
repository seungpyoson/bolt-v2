# Wave-2 PR1 Pin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the complete registry-disposition receipt and independent compatibility net required before any runtime-literal registry retirement work.

**Architecture:** A checked-in TOML crosswalk is anchored to the immutable registry bytes and validated independently from the live registry. A separate sink-derived TOML inventory records compatibility surfaces that source-literal scanning cannot see, while fixed old-byte, exact-wire, exact-shape, metadata, and digest fixtures make incompatible changes fail loudly.

**Tech Stack:** Python 3.12 (`tomllib`, `hashlib`, `unittest`-style self-tests), Rust 1.96.0, Serde JSON, SHA-256, TOML.

## Global Constraints

- The change is additive only: no deletions and no production behavior changes.
- Registry path: `docs/bolt-v3/research/runtime-literals/bolt-v3-runtime-literal-audit.toml`.
- Registry SHA-256: `8c8be8c3f5a533d87fc474080a25569c6a316a94e91c861ac8ec1560386c2b18`.
- Crosswalk dispositions, phases, and rationale codes are closed enums; uncertain rows use a keep disposition with `UNCERTAIN_KEEP`.
- The compatibility inventory is derived from serialization and hashing sinks, not registry rows.
- Current-to-current round trips are not compatibility evidence.
- Do not add the PR2 fence/Clippy policy, PR3 typed keys, or PR4 deletions.
