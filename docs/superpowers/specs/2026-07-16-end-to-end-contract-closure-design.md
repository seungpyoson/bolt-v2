# End-to-End Contract Closure Design

## Decision and Scope

Adopt type-centered contract closure across the Bolt-v3 target-identity and evidence-novelty paths. This design intentionally includes reusable repository-wide enforcement in PR #1429 under the user's explicit override of the usual one-issue-per-PR scope rule.

The change must close the full path:

`configuration -> validation -> planning -> runtime fields -> selection -> recovery -> selected-market requirements -> evidence identity -> novelty registry -> generated Rust -> exact-head CI`

The feature remains behavior-neutral for trading, admission, sizing, submission, settlement rules, and secret handling. Recovery must retain its pre-PR behavior and must not depend on evidence-only metadata.

## Core Invariants

1. A configured target identity is parsed once into a validated type. Missing, non-string, empty, whitespace-only, leading-padded, and trailing-padded inputs are rejected.
2. Invalid target identities cannot be constructed through public fields, deserialization, direct family APIs, injected bindings, or strategy registry construction.
3. Lifecycle recovery consumes only lifecycle metadata. Evidence selection may require richer metadata, but those requirements cannot leak into recovery, maker resolution, or settlement.
4. Every permanent novelty numeric ID is frozen to one semantic state. Capacity, allocations, word count, generated bytes, and ID-to-semantic mappings cannot drift independently.
5. Generated Rust must satisfy the same compiler and Clippy policy as handwritten Rust.
6. A patch is not review-ready until its exact head has passed the applicable contract matrix and remote Rust evidence. Red or pending CI is reported as such.

## Architecture

### Validated target identity

Introduce `ConfiguredTargetId` as the sole representation after raw TOML parsing. Its checked constructor and custom deserialization enforce the canonical stable-field predicate. It exposes a read-only string view but no unchecked public field or mutation API.

Configuration envelopes convert the raw TOML value at their boundary. Market-family planning, runtime-field extraction, selection targets, maker targets, and selected-market requirements carry `ConfiguredTargetId` rather than `String` or `&str` where ownership permits. Public result types keep identity fields private and expose accessors.

Injected bindings receive already-validated identity data. Validation dispatch short-circuits before invoking a binding when identity parsing fails. Direct public family entry points either accept `ConfiguredTargetId` or perform the same checked conversion before any family work.

### Consumer-specific instrument views

Split the current shared outcome-instrument extraction into two projections:

- `LifecycleInstrumentContext`: only fields required by position recovery, interval-end tracking, outcome direction, and settlement lifecycle.
- `EvidenceMarketIdentity`: the complete stable evidence identity, including provider metadata such as negative-risk mode and ordered outcome/token identity.

Core market discovery constructs only fields required to resolve the market and instruments. Maker resolution consumes this core result directly. The taker explicitly enriches the core result into `EvidenceMarketIdentity` and fails closed when required stable evidence metadata is unavailable. Recovery constructs only the lifecycle projection and therefore cannot fail because evidence-only metadata is absent. There is no fallback or default identity path.

The pinned Polymarket adapter is the production provenance gate. At Nautilus Trader revision `a192a89f7a24e435cfba7a45b6dcd6de14622967`, Gamma parsing rejects a market whose `negRisk` field is absent instead of fabricating `false`; explicit `false` and `true` remain distinct. Cache, refresh, deserialization, and direct-construction paths may still present incomplete instruments, so execution lookup removes their signing contract and limit, market, and batch submissions are denied before signing. Repo-side projection tests may construct incomplete instruments to prove lifecycle isolation and taker fail-closed behavior, but no production path may fabricate field presence.

### Selected-market requirements

`SelectedMarketRequirement` becomes constructible only through checked constructors or checked deserialization. Its configured target identity and derived selected-market key are immutable after construction. Direct family requirement builders use the same validated identity type, preventing inconsistent identity/key pairs.

### Permanent novelty registry

The verifier owns a frozen tuple containing every `(id, producer_kind, semantic_state)` mapping, not merely ranges or selected anchors. It rejects additions, deletions, renumbering, owner changes, or semantic swaps unless the frozen contract is deliberately amended. It also requires every strategy-produced entry-block reason constant to have a category mapping.

The generator emits capacity and word count using Clippy-clean `div_ceil`, plus a compile-time equality assertion. The generated file remains byte-compared with generator output and must compile in the normal Rust lanes.

## Data and Error Flow

1. Raw configuration enters through TOML.
2. `ConfiguredTargetId::try_from` rejects malformed values before family dispatch or strategy construction.
3. Validated configuration reaches family planning and runtime construction.
4. Family discovery resolves the core market without reading evidence-only metadata.
5. Taker selection explicitly enriches the core market into a complete `EvidenceMarketIdentity`; missing evidence metadata rejects only that evidence contract, never maker resolution or recovery.
6. `EvidenceEpisodeId` independently validates all stable components as defense in depth.
7. Producer canonical-state mapping resolves to a frozen registry entry before payload/claim ordering proceeds.

Errors remain typed and fail closed. Validation errors name the field and boundary. No path silently converts a malformed identity into `None` where the caller could interpret it as ordinary market absence.

## Contract Matrix

Tests must cover every boundary and consumer, not only the central wrapper:

- Raw configuration: missing, non-string, blank, whitespace-only, leading padding, trailing padding, and valid identity.
- Registry build/register: invalid identity cannot construct or start a strategy.
- Injected bindings: invalid identity short-circuits before the binding is called.
- Direct family APIs: validation, planning, runtime fields, selection, and requirement construction reject invalid identities.
- Selection targets: maker and taker carry the validated identity.
- Public types: malformed deserialization and post-construction mutation are impossible.
- Lifecycle recovery: succeeds without evidence-only metadata.
- Evidence selection: fails closed when required stable evidence metadata is missing and succeeds when complete.
- Internal whitespace: legitimate outcome labels remain accepted.
- Novelty registry: all permanent ID-to-semantic pairs are pinned; capacity and allocation mutations fail.
- Generated Rust: byte determinism, compile-time capacity assertion, format, compiler, and Clippy checks.
- Producer semantics: canonical mapping, duplicate suppression, payload-build retryability, and writer-failure claiming.

## Verification Workflow

Use local non-compile checks while editing: formatting, Python verifier tests, generated-byte verification, runtime-literal audit, source-fence, dependency policy, and diff checks.

Before broad remote CI, run the smallest permitted Rust Probe that covers generated compilation and the target-identity/recovery tests. Respect the repository's two-probe limit. After the slice is coherent, push the exact head and run full remote verification. Review begins only after results are terminal and adjudicated.

The review request must include the exact SHA, the contract matrix, and the actual CI state. It must not label failures unrelated without a demonstrated causal trace.

## Migration Strategy

1. Repair the current Clippy and recovery regressions to restore a compilable baseline.
2. Add failing contract tests for raw parsing, direct APIs, registry construction, selected requirements, recovery/evidence separation, and frozen semantic mappings.
3. Introduce `ConfiguredTargetId` and migrate producers and consumers in one coherent slice; remove superseded string validators and duplicate construction paths.
4. Split lifecycle and evidence projections; keep recovery behavior stable.
5. Harden selected-market requirement construction and deserialization.
6. Regenerate the novelty registry with complete semantic freezing and Clippy-clean arithmetic.
7. Run local gates, scoped Rust Probe, full exact-head remote CI, and whole-PR adversarial review.

## Non-Goals

- No trading, admission, sizing, order-submission, or settlement-policy change.
- No evidence persistence, retirement, or Capsule recovery implementation.
- No alternate config format, compatibility adapter, fallback identity, or second validation path.
- No live operation, deployment, merge, or trading authority.

## Completion Criteria

The work is complete only when all contract-matrix cases pass, generated output is deterministic and Clippy-clean, recovery is independent of evidence-only metadata, every identity-bearing public path uses the validated type, all exact-head required CI is green, and a whole-PR adversarial review reports no unresolved substantive findings.
