F1 — BLOCKING (code defect): Keyword-argument bypass in execution-edge detection
File/symbol: scripts/verify_fixture_git_helper_usage.py — GitFixtureVisitor.visit_Call / _execution_command_index
Concrete failure path at this head: _execution_command_index always returns 0 (the first positional argument index) for every recognized execution function. visit_Call then does:
command = (
    node.args[command_index]
    if command_index is not None and command_index < len(node.args)
    else None
)
When the command is passed as a keyword argument (args=, command=, cmd=), node.args is empty, the guard 0 < 0 is False, command becomes None, and no violation is flagged. visit_List catches list literals in keyword positions by accident (it visits all ast.List nodes), but string and tuple commands passed as keywords are completely invisible — there is no visit_Constant, no visit_Tuple, and no visit_JoinedStr.
Verified with violations_in() at head:

subprocess.getoutput(cmd="git status")
subprocess.Popen(args=("git", "commit"))
subprocess.check_output(args="git status", shell=True)
subprocess.run(args=["git", "commit"])
Controls (positional forms) all produce violations — confirmed.
Why existing tests/fences miss it: test_verify_fixture_git_helper_usage.py tests 13 execution-edge patterns, all with positional arguments. No test passes the command as a keyword argument. The PR body documents one known limit ("an opaque callable in the command position is unresolvable") but does not mention keyword arguments.
Smallest systematic fix: In visit_Call, after the positional-arg check, scan node.keywords for keyword arguments whose value resolves to git.
