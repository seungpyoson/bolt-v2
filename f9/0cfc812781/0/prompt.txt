F2 — Shutdown grace equals NT's own worst-case stop budget; bo

NT's own shutdown consumes exactly that budget: initiate_shutdown() sets shutdown_deadline = now + delay_post_stop (5s, node.rs:1457-1460), then finalize_stop() runs disconnect_clients() bounded by timeout_disconnection (10s, await_engines_disconnected) and kernel stop bounded by timeout_shutdown (10s).

So shutdown_grace == NT_stop_budget, with zero margin. Any NT shutdown that uses its full budget — a perfectly normal, healthy one — hits the grace exactly. Combined with F1, a post-Running capture failure on a node whose clients are slow to disconnect will:
1. take the pre-Running branch (F1),
2. exhaust the 25s grace against NT's 25s stop,
3. abandon run_future mid-finalize_stop(),
4. return RuntimeCaptureStartupShutdownTimeout.

The same zero-margin problem applies to the ShuttingDown | Stopped deadline branch at 2285.

Fix: derive the grace as NT's stop budget plus slack (or make it its own config field). Reusing the strategy-free stop bound verbatim is the root of it — see F9.
