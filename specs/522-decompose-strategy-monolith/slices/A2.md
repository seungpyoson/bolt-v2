# Slice A2 — consolidate `OutcomeSide` into the market-family layer + relocate side-using math

**Epic**: #522 | **Spec**: `../spec.md` | **Plan**: `../plan.md` | **Class**: behavior-preserving move (cross-cutting type) | **Stacks on**: A1 (PR #524)

> Prereq: A1 lands `src/bolt_v3_taker_signal.rs` and consolidates numeric primitives
> (incl. `BPS_DENOMINATOR`) into `bolt_v3_numeric`. A2 branches from A1's head; rebase if A1 changes.

## Goal

Remove the strategy-local `OutcomeSide` (a cross-cutting market-side type, 93 refs,
duplicating `bolt_v3_market_families::…::UpdownOutcomeSide`) by homing the canonical
side type in the market-family layer, then relocate the OutcomeSide-using decision math
into the existing shared `bolt_v3_taker_signal`. Behavior-preserving; no logic change.
**Partially resolves findings-doc #13** (OutcomeSide); A3 completes it (`CandidateMarket`).

## Verified facts (current-main; re-confirm at slice HEAD)

- `OutcomeSide` (`binary_oracle_edge_taker.rs:6883`) and `UpdownOutcomeSide`
  (`updown.rs:475`) are **structurally identical**: variants `Up`/`Down`, derives
  `Debug,Clone,Copy,PartialEq,Eq`, **no** custom `Display`/`serde`/`as_str` impls. A
  pure type-identity unification, not a semantic merge.
- `MarketSelectionOutcome` (`mod.rs:161`, `Current`/`Next`) is a different concept — out of scope.
- **No import cycle**: `bolt_v3_market_families` and submodules do not import
  `crate::strategies` (grep: 0). `bolt_v3_taker_signal` may import the side type from
  `bolt_v3_market_families` safely (it already imports only `bolt_v3_numeric`).
- 93 `OutcomeSide` refs in the strategy: struct fields (`OpenPositionState`/`PendingEntryState`/`ExitEvaluation`/`EntryEvaluation`), fee/book/instrument selection, position-state mutation, the 2 side-using math fns, evidence label, `EntryPricingBlockReason` variants, tests.

## Moves

### Target 1 — home the canonical side type in `src/bolt_v3_market_families/`
- Promote `UpdownOutcomeSide` to a **`pub`** type (proposed name `OutcomeSide`, re-exported from `mod.rs`; naming is an open question below). Same variants/derives. updown.rs internal uses switch to the public path.

### Target 2 — `src/bolt_v3_taker_signal.rs` (exists from A1) gains the side-using math
- fns: `compute_worst_case_ev_bps` (`:7056`, uses `BPS_DENOMINATOR` from `bolt_v3_numeric` + the side type), `choose_entry_side` (`:7091`, returns the side type), `outcome_side_evidence_label` (`:6889`)
- input structs: `WorstCaseEvInputs` (`:7026`), `SideSelectionInputs` (`:7084`)
- new import: the side type from `bolt_v3_market_families`; `BPS_DENOMINATOR` from `bolt_v3_numeric`.
- Relocate the 5 pure-unit tests: `task4_worst_case_ev_uses_side_specific_bounds_and_fees_fail_closed` (`:16559`), `task4_side_selection_*` (`:16631`,`:16643`,`:16654`,`:16674`).

### Strategy file
- Replace the local `enum OutcomeSide` with `use crate::bolt_v3_market_families::OutcomeSide;` (or the chosen name); the 93 refs resolve by import (compile-error-driven; no logic change). `EntryPricingBlockReason` variants now carry the shared type (Debug output unchanged — same variant names). Side-using math now imported from `bolt_v3_taker_signal`.

## Behavior preservation & gate (A1 lessons)

- Identical enum (variants/derives) → match exhaustiveness + Debug output unchanged; no serde/Display to drift.
- **Run the FULL local gate before push** (see [[project_bolt_v2_ci_full_gate]]): `cargo fmt --check` + `verify_bolt_v3_{runtime_literals,naming,provider_leaks,core_boundary}.py`. Moving the side type + math into `bolt_v3_*` modules (in naming/boundary scan scope) means: (a) **core-boundary** fence must allow `bolt_v3_taker_signal → bolt_v3_market_families` (verify; if disallowed, home the side type in a lower neutral module instead); (b) **naming** fence must accept the moved field/fn names (none currently look forbidden, but confirm); (c) no new bare literals (the math uses named consts).
- RED/GREEN: pin one `compute_worst_case_ev_bps` and one `choose_entry_side` case before/after the move; all 5 relocated tests pass in `bolt_v3_taker_signal`.

## Acceptance

- Strategy file shrinks (enum + 2 fns + 2 structs + 5 tests removed; imports added); `OutcomeSide` no longer defined in `strategies/`.
- One canonical side type; no duplicate; CI green; 6-model unanimous; operator merge permission.
