**Epic**: #522 | **Spec**: `../spec.md` | **Plan**: `../plan.md` | **Class**: behavior-preserving move (cross-cutting type unification) | **Stacks on**: A1 (PR #524, head `2fa9209b`)

## Goal

Remove the strategy-local `OutcomeSide` (a cross-cutting binary-market side type,
93 refs, structurally identical to `bolt_v3_market_families::updown::UpdownOutcomeSide`)
by homing **one** canonical side type in the market-family layer, then relocating the
side-using decision math into the existing shared `bolt_v3_taker_signal`.
Behavior-preserving; no logic change. **Partially resolves findings-doc #13**
(OutcomeSide); A3 completes #13 (`CandidateMarket`).

## Verified facts (re-confirmed at slice HEAD `5db2823e`; line numbers current)

- **Type identity is exact.** `OutcomeSide` (`binary_oracle_edge_taker.rs:6877-6881`)
  and `UpdownOutcomeSide` (`updown.rs:474-478`) both derive **exactly**
  `Debug, Clone, Copy, PartialEq, Eq`, variants `Up`/`Down`, and have **zero** custom
  impls (no `Display`/`serde`/`as_str`; grep-confirmed on both). This is a pure
  type-identity unification, not a semantic merge.
- **Ref counts.** `OutcomeSide`: 93 refs, **all** in the strategy file. `UpdownOutcomeSide`:
  6 refs, **all** in `updown.rs` (enum def + `UpdownOutcomeInstrument.side` field +
  `::Up`/`::Down`). **No third module** references either type.
- **No import cycle.** `bolt_v3_market_families` (and submodules) do not import
  `crate::strategies` (grep: 0). `bolt_v3_taker_signal` already imports only
  `bolt_v3_numeric`; adding an import of the side type from `bolt_v3_market_families`
  is acyclic.
- **Core-boundary fence permits this.** `scripts/verify_bolt_v3_core_boundary.py` is a
  *symbol-placement* check on 4 named files (`bolt_v3_config.rs`, `providers/mod.rs`,
  `archetypes/mod.rs`, `market_families/mod.rs` — the last only forbids
  `RotatingMarketFamily` patterns). It does **not** constrain the import graph and does
  **not** cover `bolt_v3_taker_signal.rs`. Adding `pub(crate) enum OutcomeSide` to
  `market_families/mod.rs` is fence-safe.
- **Naming fence clear.** `docs/bolt-v3/research/naming/nt-owned-name-audit.yaml` has
  **no** entry for any moved name (`OutcomeSide`, `compute_worst_case_ev_bps`,
  `choose_entry_side`, `outcome_side_evidence_label`, `WorstCaseEvInputs`,
  `SideSelectionInputs`, or their fields). None are NT-owned. Moving these into a
  `bolt_v3_*.rs` module (in the fence's scan scope) is safe.
- **No hidden deps in the moved math.** `compute_worst_case_ev_bps` uses only
  `sanitize_probability`, `is_positive_finite`, `is_non_negative_finite`,
  `clamp_probability`, `UNIT_F64`, `ZERO_F64` (already imported into `taker_signal`)
  plus `BPS_DENOMINATOR` (in `bolt_v3_numeric` since A1 — `taker_signal` adds it to its
  import). `choose_entry_side`, the 2 input structs, and `outcome_side_evidence_label`
  reference only the side type + std.

## Decisions (resolving A2's prior open questions)

1. **Side-type home + name → `pub(crate) enum OutcomeSide { Up, Down }` in
   `src/bolt_v3_market_families/mod.rs`.** It is the canonical binary outcome side,
   used generically by the taker; `mod.rs` is the
   family-layer shared home (fence-safe). `updown.rs` drops its local
   `UpdownOutcomeSide` and uses `super::OutcomeSide` (6 refs swapped, incl.
   `UpdownOutcomeInstrument.side: OutcomeSide`). The strategy imports
   `crate::bolt_v3_market_families::OutcomeSide`. Name `OutcomeSide` (not
   `BinaryOutcomeSide`) — matches the strategy's existing vocabulary and the 93 call
   sites; concise; no fence conflict.
2. **Side-using math home → `bolt_v3_taker_signal`** (alongside A1's taker math). These
   are taker *decision* logic, not market-family structure. Relocate as `pub(crate)`:
   `WorstCaseEvInputs`, `compute_worst_case_ev_bps`, `SideSelectionInputs`,
   `choose_entry_side`, and `outcome_side_evidence_label`. Kept as **free functions**
   (not promoted to methods on the side type) so A2 stays a *pure relocation* — call
   sites change only their import path, not their call form. (Promoting
   `outcome_side_evidence_label` to an `OutcomeSide::evidence_label()` method is a
   defensible future cleanup but is deferred to preserve the pure-move property.)
3. **One PR.** The type-home, 93-ref swap, and math relocation are interdependent (the
   math takes the side type) and form one coherent "OutcomeSide consolidation" scope
   ([AGENTS.md#repo-rule-strategies-produce-intent-only](../../../AGENTS.md#repo-rule-strategies-produce-intent-only)).
   Splitting would double the heavy 6-model gate for a mechanical,
   compile-driven change
   ([AGENTS.md#repo-rule-strategies-produce-intent-only](../../../AGENTS.md#repo-rule-strategies-produce-intent-only)).
   Mitigation for the larger surface: run the **full local gate**
   before push and RED/GREEN-pin the math (below). Fallback: if review insists, split
   into A2a (type-home + 93/6-ref swap) then A2b (math relocation) — but default is one.
