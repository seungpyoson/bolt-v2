# Implementation Plan: Risk-Reservation Substrate (gate-owned safety ledger)

**Branch**: `712-positional-sizing-engine` (design authoring; substrate implementation branches from its own tracking issue) | **Date**: 2026-06-25 | **Spec**: `specs/973-risk-reservation-substrate/973-risk-reservation-substrate-spec.md`
**Input**: Feature specification from `specs/973-risk-reservation-substrate/973-risk-reservation-substrate-spec.md`. Tracking: #973. Depends on #711; consumed by #712; armed live by #688.

## Summary

Build the atomic risk-reservation substrate: one bounded context that, on a single coherent risk-state version, reserves collateral + realized-loss budget + equity-floor stress loss + concentration buckets + position/order capacity before any order is admitted. It computes all authoritative risk itself from a substrate-resolved, certified instrument-risk descriptor; exposes a versioned advisory read view and a type-bound write path; owns a closed SafetyAction set; and activates descriptor/policy changes through a prepared-epoch atomic cutover. It extends the existing reservation primitive rather than forking it, and consumes NT's order/position/fill truth rather than rebuilding it. It is the next iteration of the consolidated capital-admission gate (#507 → #658 → #711): it REUSES the existing loss governor, kill switch, reservation ledger, NT runtime feeds, and restart recovery as single sources (spec FR-064) and adds only atomicity-on-one-version, descriptor authority, provenance, and epoch cutover — it does not re-fragment what #658/#673 consolidated to end the "three reimplemented loss governors" duplication.

## Architecture — one bounded context, single-job components (FR-063)

One-way dependencies; only the state owner mutates authoritative risk state:

- **InstrumentRiskRegistry** — certified descriptor activation + active-version resolution (FR-010..FR-015).
- **RiskKernel** — pure evaluation; the shared evaluator for the provenance-free preview and the commit (same kernel, FR-025); two loss metrics; bounded/IO-free (FR-003, FR-005, FR-008).
- **RiskClassifier** — pure, authoritative complete bucket derivation (FR-004).
- **RiskStateOwner** — sole mutation + serialization domain + monotonic version (FR-006, FR-007).
- **ReservationLedger** — reservation state transitions under the state owner, driven by the FR-043 lifecycle state machine (Reserved … Settled + Cancel/Expired/Unknown/ReconciliationRequired); extends `bolt_v3_capital_reservation.rs` (FR-001, FR-043..FR-047).
- **AdmissionService** — compare → evaluate (ALL stateful caps + reused kill-switch/governor state bound to one version) → reserve → token; no post-reservation rejection path; atomic permit consumption (FR-001, FR-002, FR-022, FR-065, FR-066).
- **LifecycleReconciler** — NT-event + restart reconciliation of reservations against NT truth (FR-040, FR-041, FR-043..FR-047).
- **RiskViewPublisher** — immutable advisory versioned views + the `ActiveDescriptorView` read contract and the provenance-free `RiskPreviewInput`/`RiskAssessment` path (FR-020, FR-021, FR-024, FR-025).
- **SubmissionAuthority** — token consumption + `AdmittedOrder` construction as the ONLY type the live submit boundary accepts (FR-022, FR-026, FR-040).
- **EpochManager** — prepared-epoch validation + atomic cutover + policy envelope (FR-050..FR-053); **SafetyAction** verifier with bounded reduction-proof domain (FR-030..FR-032).

## Slices (dependency-ordered; each fails closed; evidence class per slice)

- **S0 — Foundation, seams, source-proof (NT + consolidated stack), pool-ownership fence.** Define the contracts; stand up the single serialization domain + monotonic version over the existing ledger; skeleton the single-job components; **source-prove NT submission-idempotency / order-state reconciliation / restart recovery AND the existing consolidated stack (loss governor, kill-switch cancel/flatten/halt, reservation ledger, NT runtime feeds — #505/#507/#658/#673)**, and wire reuse (FR-064) rather than new machinery; record gaps. **Select and NAME the Phase-1 pool-ownership lease authority and stand up the FR-067 fence — an exclusive per-`pool_id` lease + monotonically increasing fencing token validated on every durable risk-state/reservation mutation, fail-closed on lease loss, successor reconciles (FR-041) before new risk — as a BLOCKING S0 deliverable, not deferred prose.** Off by default. *Evidence: review/grep (agnostic seam, single domain, reuse-not-duplicate) + source-proof notes + named lease authority + SC-014 split-brain fencing test (stale owner cannot commit after transfer) + `cargo test` skeleton; fmt/clippy/deny.*
- **S1 — RiskKernel + RiskClassifier (pure).** The shared evaluator (two loss metrics, bounded/IO-free, documented complexity) + authoritative bucket derivation. *Evidence: unit + property tests (loss-metric distinctness, bucket completeness, missing-attribute fail-closed); complexity note.*
- **S2 — Compare-and-reserve.** The atomic transaction across all dimensions on one version, with ALL stateful caps and the reused kill-switch/governor state bound to that one version (FR-065/FR-066 — no post-reservation rejection path); the view publisher, the `ActiveDescriptorView`, and the provenance-free `RiskPreviewInput` preview that shares the pure kernel with commit (FR-024/FR-025). *Evidence: SC-001 concurrency/property test (correlated candidates never breach budget) + SC-002 (caller risk numbers ignored) + stale-view rejection test + SC-013 (every cap inside the transaction; no post-token rejection) + preview≡commit kernel test.*
- **S3 — Descriptor registry + certification.** Active-version resolution, attestation verification, unknown-state envelope, immutability + revaluation, separation of duties. *Evidence: SC-003 fail-closed tests (stale version rejected, uncertified fail-closed, unmapped outcome → envelope + halt).*
- **S4 — Provenance + idempotency + reconciliation + submit boundary.** Atomic permit consumption; durable submission-intent before first send (via NT submission per S0); restart/reconnect reconciliation of reservations against NT truth; the `AdmittedOrder`-only live submit boundary (FR-026) constructible solely by the submission authority via a Reserved→Submitted transition. *Evidence: SC-004 restart test (exactly one live order + one reservation + coherent version); replay returns existing result; SC-012 bypass-prevention (compile-fail + dependency-boundary: nothing but `AdmittedOrder` reaches live submit).*
- **S5 — SafetyAction path.** Closed operation set; recomputed dual proof; bounded reduction-proof domain; admissible while frozen. *Evidence: SC-005 tests (reduce-only admitted while frozen; disguised risk-increase rejected; bounded proof domain).*
- **S6 — Prepared-epoch + policy envelope + atomic cutover.** Staged bundle validation + revaluation + atomic cutover; allowed-range/cross-field-invariant guard; verify each `BandCoverageAttestation` as a COMPLETE canonical artifact (full field set + signature/MAC + non-expiry/non-revocation) and bind its exact content digest into the epoch (FR-050), failing closed on a named-but-unverified attestation. *Evidence: SC-006 cutover test (no mixed old/new observable; partial-failure → no-new-risk) + catastrophic-but-valid config rejected + attestation digest/authentication verification test (named-but-unverified → fail closed).*
- **S7 — Bounded work + lifecycle priority + load envelope.** Lifecycle/SafetyAction priority; bounded queues; overload shedding; supported offered-load envelope + fairness. *Evidence: SC-007 capacity/overload test (latency bounds hold inside envelope; shed fail-closed above it; no lifecycle starvation).*
- **S8 — Reservation lifecycle + event integrity.** The FR-043 state machine driving FR-044 partial fills (filled→position exposure, remainder retained, version advances once), FR-045 cancel/replace (no release without venue confirmation; combined old+new reserved; late fill covered), FR-046 settlement release (held until terminal-final + reconciled), and FR-047 event integrity (idempotent duplicates; out-of-order/gap → ReconciliationRequired + block new risk). Maps NT fill/settlement events → reservation transitions (NT owns fill truth; the substrate owns the multi-dimensional reservation mapping NT does not). Depends on S2 (reserve) + S4 (reconcile). *Evidence: SC-011 lifecycle permutation tests (partial-fill→cancel→late-fill, replace-in-flight, settlement-revision, duplicate, sequence-gap) asserting aggregate reserved risk never falls without authoritative confirmation.*

## Complexity Tracking

| Decision | Why needed | Simpler alternative rejected because |
|----------|------------|--------------------------------------|
| Single serialization domain | Atomic multi-dimension reserve on one version is the only way the portfolio loss cap is a real control | Advisory cross-batch checks are TOCTOU; a cap that is not atomically reserved is a reporting number, not a control |
| Substrate-owned descriptor authority | All authoritative risk flows from one input; a caller-selected or stale descriptor reserves correct numbers for wrong economics | Trusting caller-supplied risk or a caller-named version is the failure mode that drove the split |
| In-process capability provenance (P1) | Enforces a single sizing authority at compile time without IPC auth complexity | A serialized permit needs signing/MAC; deferred to the forward path until provenance must cross a process boundary |
| Reuse loss governor + kill switch, not rebuild | #505/#507/#658/#673 already consolidated these to end three-way loss-governor duplication; the substrate adds only atomicity/descriptor/provenance/epoch | Rebuilding them re-fragments the consolidated stack and reintroduces the dual path the consolidation fixed |
| Explicit reservation lifecycle state machine (S8) | Premature release of a multi-dimensional reservation after partial fill/cancel/replace/settlement is the single biggest production risk | Releasing on local intent (send/cancel/timeout) lets a second order reuse collateral/loss capacity while the first can still fill — breaching the budget the gate exists to enforce |
| Phase-1 single-owner-per-pool + normative fence (FR-067/SC-014) | Honest multi-instance support without committing a distributed transactional backend before it is needed; the fence is a testable FR + split-brain test + named authority, not prose | Claiming many-process shared-pool support while deferring the store/isolation/fencing mechanism is an undecided implementation masquerading as a capability; leaving the fence in assumptions lets a paused old owner resume and mutate the ledger after ownership transfers |
| `AdmittedOrder`-only submit boundary | Fencing candidate *construction* is necessary but not sufficient; the live send must also reject any non-admitted type | A module could bypass sizing/admission via a lower-level submit interface if the boundary accepts raw orders |
| Every stateful cap inside the compare-and-reserve | A cap that can reject after a token issues creates a post-reservation rejection path, reservation rollback, and duplicated cap authority | Keeping notional/count caps downstream of the reservation leaks reserved capacity on rejection and reintroduces a TOCTOU gap |
